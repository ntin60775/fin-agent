# Раунды приёмки и багфикс после основного цикла

Полная схема: `docs/reference/acceptance-rounds.md`. Краткие инварианты:

- Замечания к **незакоммиченному диффу текущего тикета** (стадия stop-before-commit) —
  правятся в том же ране, новый тикет НЕ заводится.
- Замечания к **смерженной работе активного плана** — новый тикет раунда
  `docs/plans/<slug>/NN-acceptance-round-K.md` в том же плане, один `/ship`-ран на раунд.
  Замечания фиксируются в тикете списком «было / надо» (чекбоксы приёмки) ДО старта рана.
- Замечания **после архивации плана** — новый багфикс-контракт (mp-diagnose → план/файл-план),
  не «мелкая правка поверх».
- Архивные тикеты не переоткрываются; план остаётся `active`, пока приёмка не сошлась.
- Пакетирование: однородные замечания — один тикет-пачка; делить только при разной
  природе проверки (docs/lint vs код/прогоны). Тикет на каждое замечание — не делать.
- Гейты раунда полные: worktree → правки → регресс затронутых сценариев (не только
  целевых) → инкрементальное ревью дельты → stop-before-commit.
