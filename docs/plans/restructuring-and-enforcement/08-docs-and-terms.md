# 08: Доки, термины и записи решений

**What to build:** KB и код называют одно и то же одними словами, решения
грилла переживают план. Термины в `CONTEXT.md` с «не говорить»:
реструктуризация, принудительное удержание, неприкосновенный остаток, версия
условий (Q13). `finance_core/README.md` описывает версии условий, стык эпох,
принуждение и варианты ровно по коду. Записи решений в `docs/decisions/` — по
критерию Q39 плана penalties (решение, меняющее долговременное правило движка):
версии условий; принуждение в кассе и прокате.

**Blocked by:** 01–07 (документация описывает финальное состояние всех
способностей).

## Приёмка

- [ ] Термины в `CONTEXT.md` с определениями из решений грилла и «не говорить»:
  реструктуризация (не «рефинансирование»), принудительное удержание (не
  «арест»), неприкосновенный остаток (не «прожиточный минимум»), версия
  условий (не «правка сделки»); термины употреблены в README и докстрингах
  одинаково.
- [ ] Термин «взыскание» не слился с существующими: роль контрагента и второй
  приоритет остаются своими словами; «арест» остаётся у кошелька.
- [ ] Новые публичные имена экспортированы в `finance_core/__init__.py`
  осознанно — список полон, лишнего не завезено.
- [ ] Записи решений в `docs/decisions/` (версии условий; принуждение) —
  `node_type: decision`, связаны, цитируют номера вопросов грилла; линт KB
  канонической копией чист, индекс перестроен.
- [ ] Каждое решение Q1–Q14 и тикетных гриллов либо покрыто записью, либо
  помечено плановым — проверяется грепом по номерам.
- [ ] `finance_core/README.md` описывает ровно то, что делает код; сценарные
  тесты зоны прогоняет оператор.

## Грилл тикета

Грилл исполнен автономно по поручению оператора (2026-10-02): вопросы уровня
«как» решены рекомендациями ниже; вопросов уровня «что», требующих оператора,
не возникло. Состав слой решён планом (Q13), тикет решает форму.

❓ **08-Т1** — **Какие записи решений заводить.**

➡️ Рекомендация (принята): две — «Версии условий сделки» (Q1, Q5, Q6, Q11:
эпохи суммы, ставки и графика; стык вхождений; граница с начислением) и
«Принуждение в кассе и прокате» (Q2, Q4, Q7, Q8, Q12: факт и статус, порог
зоны, приоритет без согласия). Единица одного дела (Q3, Q9) и вариант (Q10)
собираются из существующих решений (записи penalties) — отдельные записи
дублировали бы их. Критерий — прецедент Q39 плана penalties: запись получает
решение, меняющее долговременное правило движка.

*Отклонено:* запись на каждый вопрос — шум дублей; без записей — решения
переживают план только в грилле, будущий цикл их не найдёт.

❓ **08-Т2** — **Порядок работ и финальная проверка.**

➡️ Рекомендация (принята): термины → записи решений → README → экспорт (глоссарий
раньше кода: докстринги ссылаются на термины); финальная проверка: линт KB
канонической копией и `index`, `python3 -m pytest tests/`, сверка списков
(экспорт против Scope, README против Done, термины против докстрингов),
сценарные тесты зоны — оператор.

*Отклонено:* линт вместо тестов — линт про KB, не про код; автогенерация README
из кода — пересказ сигнатур без смысла.
