# 01: Модель взаиморасчётов — контрагент, сделка, движение

**What to build:** движок держит взаиморасчёты с контрагентом в обе стороны.
Контрагент — субъект с уидом, именем, типом, подтипом и группами (контуры: семья,
работа, жильё, долги). Сделка опознаётся уидом, несёт условия, направление (я должен
или мне должны) и роли: кому должен и за кого — получатель выгоды. Движение — факт:
дата, сумма, направление, кому уплачено, с какого кошелька, назначение (на что ушли
деньги). Остаток по сделке и сальдо по контрагенту считаются из условий и движений,
а не хранятся. Передача долга хранится историей: от кого к кому, когда, сколько было
на момент передачи и насколько сумма изменилась.

Передача члену семьи — такой же расход из кассы владельца, только с назначением и
отдельной строкой в отчёте. Доходы и счета остальных членов семьи в модель не
входят: считается только своё.

Новая форма вводится **рядом** со старой: строковое имя контрагента продолжает
работать, ничего не удаляется. Это расширение перед переездом, а не замена.

**Blocked by:** нет, можно начинать сразу.

- [ ] Контрагент опознаётся уидом — он же имя файла карточки; имя нужно только для
      показа. Тип и подтип берутся из объявленных наборов, опечатка отклоняется
- [ ] Группы — свободные метки с обязательным стартовым набором (семья, работа,
      жильё, долги); групп у контрагента может быть несколько
- [ ] Ссылка на необъявленного контрагента — ошибка с перечнем объявленных, как
      сейчас для счетов; сделки без контрагента не бывает
- [ ] Сделка опознаётся уидом и несёт условия (сумма, ставка, правило графика) и
      направление («я должен» / «мне должны»)
- [ ] Кошелёк — сущность движка, опознаётся уидом: тип (карта, счёт, наличные,
      электронный кошелёк — список расширяемый), фактический остаток, признак
      доступности
- [ ] Остаток кошелька подписанный: минус на кредитном — долг, а не дыра; плюс на
      кредитном — свои деньги (переплата), а не свободный лимит
- [ ] Свободный лимит кредитного кошелька показывается, но деньгами не считается
- [ ] Сделка бывает без остатка — регулярный расход (жильё, подписки): он не
      закрывается и досрочке не подлежит
- [ ] Правило графика несёт флаг сдвига по выходным; платёж сдвигается вперёд
      (поведение — в 02; приходы считает касса — в 03)
- [ ] У сделки есть приоритет: обязательный график или второй приоритет; поведение
      второго приоритета описано в 02
- [ ] У сделки есть роль «за кого» — получатель выгоды, если платишь не за себя
      (например, за члена семьи); у движения может быть переопределение
- [ ] Роль контрагента — «кредитор», «должник» или «и то и другое» — выводится из
      суммы по его сделкам в обе стороны и не хранится ни в одном поле
- [ ] Канал платежа (через кого) и финансирующий кошелёк — на движении; у сделки есть
      значения по умолчанию, движение может их переопределить
- [ ] Сделки, гасящиеся вместе, помечаются одной единицей закрытия; поле объявлено,
      правило использует его в 02
- [ ] Расчётный остаток по сделке считается из её условий и движений на дату —
      чтобы его можно было сверить с фактическим
- [ ] Сальдо по контрагенту — сумма по всем его сделкам в обе стороны; ни сальдо, ни
      остаток не хранятся
- [ ] Сальдо — отчётная величина: зачёт (уменьшение одного долга другим) не
      производится, проценты не прощаются
- [ ] Передача долга хранится записью (дата, прежний и новый держатель, сумма на
      момент передачи, изменение суммы) и создаёт версию условий: прежние
      сохраняются, новые действуют с даты передачи
- [ ] Каждое движение помнит, кому уплачено на тот момент, и несёт назначение
- [ ] Платёж кассы ссылается на контрагента и несёт назначение — вместо строки с
      именем; сама строка живёт до 09
- [ ] Передача члену семьи — расход из кассы владельца с назначением; доходы и счета
      остальных членов семьи в модель не входят
- [ ] Синтетические тесты движка зелёные; старый способ вызова не сломан
