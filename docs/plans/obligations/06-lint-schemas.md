# 06: Схемы карточек — линтер проверяет обязательные свойства

**What to build:** у типа карточки объявлены обязательные свойства и допустимые
значения; проверяет линтер базы знаний, и нарушение схемы — ошибка, а не
предупреждение. Поля схемы живут в свойствах карточки (frontmatter), а не в её теле:
тело — проза, которая в расчётах не участвует.

Схемы объявляются там, где живут карточки: у карточек контрагентов и кошельков — в
базе знаний финансовой зоны, а не в архитектурной. Форматы строки реестра и записи
журнала объявляются там же, но проверяет их тест зоны (07), а не линтер: строка —
не карточка. Объявление **машиночитаемо** — линтер читает его сам, без правки кода.
Иначе новый тип карточки потребует программиста, а перечень типов в документе и в
коде разойдутся — как уже разошлись: в линтере есть типы, которых нет в онтологии.

Инструмент и онтология — вендорный пакет. Проверка схем — местное расширение, и оно
осознанно расходится с исходным пакетом.

Документ в папке карточек без объявленного типа — ошибка. Без этого требование «все
карточки покрыты схемами» не проверяется: карточка просто не попадёт под проверку.

Поля не хватает в самой схеме — это заявка на доработку схемы, а не свободная правка
карточки.

Инструмент лежит в двух зонах одной и той же копией — он вендорный пакет. Сверка
копий по контрольной сумме — шаг приёмки тикета, а не тест: архитектурная зона
публикуема и не должна знать о соседней.

**Blocked by:** 01 — модель взаиморасчётов: схема описывает её поля.

- [ ] Схема типа карточки объявляет обязательные свойства и допустимые значения
- [ ] Объявление схемы машиночитаемо: линтер читает его без правки кода
- [ ] Перечень типов перестаёт быть двумя носителями: документ и код читают одно
      объявление
- [ ] Линтер сообщает о нарушении схемы с указанием файла и поля
- [ ] Карточка без обязательного поля не проходит линт
- [ ] Документ в папке карточек без объявленного типа — ошибка
- [ ] Схема кошелька объявляет обязательные поля: уид, название, тип, фактический
      остаток с датой наблюдения, доступность; лимит — у кредитного
- [ ] Доступность в схеме значит «можно пользоваться деньгами и лимитом»: у
      недоступного кошелька лимит остаётся виден, но к использованию его нет
- [ ] Поля схемы живут в свойствах карточки; тело остаётся прозой
- [ ] Проза карточки схемой не ограничивается
- [ ] Копии инструмента в двух зонах идентичны (сверка по контрольной сумме)
- [ ] Линт обеих зон чист на текущей базе знаний
