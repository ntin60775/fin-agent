# 03: Оценка floor в начале окна

**What to build:** прокат оценивает нехватку до минимума в момент начала окна,
а не только на шагах событий. Сегодня `_assess_floor` идёт по `main_steps`:
первый приход 25-го — голод первых 24 чисел не виден вообще, а месяц получает
ноль («оценено и покрыто»). Дыра в том же окне на старте проверяется
(`hole = _shortage(...)` от `window_start`) — floor обязан вести себя так же.
Точка оценки — начало каждого месяца (`window_start`: для первого — `start`,
для остальных — 1-е число) с входным остатком месяца; прожитое на этой точке —
минимумы месяцев до него (0 для первого), механизм из тикета 01. Месяц без
событий на основном кошельке получает оценку по началу месяца вместо None:
слепота уходит; None остаётся только там, где прихода впереди не видно
(и при `living_floor=None`).

Воспроизведение (синтетика, аудит 2026-09-22): кошелёк 0, приход 25-го числа,
минимум 3 000 — месяц 1 проката обязан показать нехватку, а не 0 и не None.

`run()` окна не имеет: граница до первого события документируется в тикете 02 —
требование этого тикета относится к прокату.

**Blocked by:** 02 — оценка в начале окна опирается на учтённое прожитое, иначе
старт месяца меряется фантомным остатком.
