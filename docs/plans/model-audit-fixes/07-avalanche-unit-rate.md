# 07: Лавина ранжирует копилку по ставке участников

**What to build:** в стратегии «лавина» единица закрытия ранжируется по самой
дорогой ставке участника, а не по нулю: сегодня `_targets` отдаёт копилке
`Decimal(0)`, и дорогая копилка уходит последней после любой standalone-сделки
с ненулевой ставкой — «лавина — дорогая ставка первой» обходит её. Ставка
копилки — максимальная ставка участника; она участвует только в ранжировании
(`_order`), на суммы не влияет. Снежный ком
(по остатку) не меняется; участие `prepay=False` и порядок внутри копилки не
трогаются.

**Blocked by:** —

## Приёмка

- [x] Синтетический тест: копилка с участником под 40 % гасится в лавине
      раньше standalone-сделки под 10 % при равном прочем (порядок виден в
      расписании месяца)
- [x] `test_avalanche_is_cheaper_than_snowball` остаётся зелёным без правки
- [x] Снежный ком не изменился: `compare_deal_strategies` по-прежнему отдаёт
      обе стратегии и их сравнение осмысленно
- [x] Копилка с `prepay=False` у любого участника по-прежнему исключена из
      досрочек (запрет не обходится правкой ранжирования)
- [x] `finance_core/README.md` (секции копилки и досрочки): ставка копилки —
      максимальная ставка участника, участвует только в ранжировании
- [ ] Синтетические тесты движка зелёные; сценарные тесты потребителя зелёные
