# 09: Досрочка на деньги, освобождённые переносом

**What to build:** вариант «перенос платежа освобождает деньги месяца → досрочка
из них» признаётся возможным, когда деньги действительно освобождаются. Сегодня
`_prepay_reason` меряет бюджет досрочки по базе (до действий варианта) и
`ImpossibleAction` отклоняет вариант — отказ по строгости выдаётся за
невозможное, хотя сам докстринг это признаёт («это отказ по строгости, а не по
невозможности»). Путь: бюджет меряется по входу варианта — собранному с
действиями, но без данной досрочки; `applied()` уже собирает вход и считает
прогноз в `price()`, поэтому проверка по входу допустима по стоимости. База не
переписывается (инвариант 10 README остаётся в силе).

**Blocked by:** 01 — бюджет (`prepay_budget`) меняется в тикете 01; проверка
должна опираться на исправленные свободные деньги.

## Приёмка

- [ ] Синтетический тест: `Move` платежа ближе к концу месяца + `Prepay` на
      освободившиеся деньги — `impossible()` возвращает None, `applied()` проходит
- [ ] Прежние отказы сохранены: досрочка больше остатка сделки; досрочка больше
      бюджета месяца, где ничего не освобождалось; мост больше лимита кошелька;
      перенос за горизонт; конфликт действий внутри варианта
- [ ] Невозможное по-прежнему `ImpossibleAction` с причиной; докстринг
      `_prepay_reason` больше не называет отказ невозможным
- [ ] База не мутируется: `base.forecast` после `applied()`/`price()` прежний
- [ ] Синтетические тесты движка зелёные; сценарные тесты потребителя зелёные
- [ ] `finance_core/README.md`: класс отказов обновлён — что невозможно, а что
      меряется по входу варианта
