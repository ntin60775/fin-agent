# 09: Досрочка на деньги, освобождённые переносом

**What to build:** вариант «перенос платежа освобождает деньги месяца → досрочка
из них» признаётся возможным, когда деньги действительно освобождаются. Сегодня
`_prepay_reason` меряет бюджет досрочки по базе (до действий варианта) и
`ImpossibleAction` отклоняет вариант — отказ по строгости выдаётся за
невозможное, хотя сам докстринг это признаёт («это отказ по строгости, а не по
невозможности»). Путь: вход = база + все действия варианта, кроме всех `Prepay`
(а не «кроме данной досрочки» — иначе проверка зависит от порядка); бюджет
месяца меряется по прогнозу этого входа — один дополнительный `forecast` на
проверку. Проверки «вместе» сохраняются: Σ досрочек месяца ≤ бюджет входа,
каждая ≤ остатка сделки; порядок действий не влияет. `applied()` уже собирает
вход и считает прогноз в `price()`, поэтому проверка по входу допустима по
стоимости. База не переписывается (инвариант 10 README остаётся в силе).

**Blocked by:** 01 — бюджет (`prepay_budget`) меняется в тикете 01; проверка
должна опираться на исправленные свободные деньги.
