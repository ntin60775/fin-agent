# 13: «Сколько набежит, если тянуть до даты»

**Суть.** Прямой вопрос заявки: сколько набежит, если тянуть месяц. Прокат
платит обязательные по графику и «тянуть» не умеет — нужен отдельный расчёт, и
он обязан считаться теми же функциями, что история.

**Сегодня.** Прокат платит обязательные из нагрузки; режима «не плачу» в
движке нет.

**Будет.** What-if расчёт «тянуть до даты»: вхождения не платятся — каждое
просрочивается со своего срока, база растёт, неустойка капает по шкале. Ответ —
разбивка на дату (тело, проценты, неустойка, издержки) и «сколько набежало за
период» — дельта по частям. Начисление и округление — те же функции, второй путь
не появляется.

**Решения грилла плана.** Исполняет R3-Q20 (отдельный what-if расчёт теми же
функциями, явный вход «вхождения не платятся»), R4-Q26 («тянуть» определено
состоянием просрочки: каждое вхождение просрочивается целиком со своего срока).
Новых решений не принимает.

**Blocked by:** 04 (разбивка по частям), 05 (база), 06 (формула).

## Приёмка

- [ ] Синтетика: долг без платежей «набежал» к дате — разбивка по частям
  (тело, проценты, неустойка, издержки) и дельта за период сходятся с ручным
  замером формулы — `tests/test_debt.py`.
- [ ] Синтетика: просрочки начинаются со своих сроков (каждое вхождение своё),
  ступени шкалы применяются по сроку каждой просрочки — `tests/test_debt.py`.
- [ ] Синтетика: при частичных платежах «тянуть» учитывает их — база растёт
  только от неуплаченного — `tests/test_debt.py`.
