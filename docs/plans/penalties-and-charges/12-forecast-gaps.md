# 12: Прогноз и сверка: части, пробелы, вопросы

**Суть.** Кредитор показывает долг по частям, и сверка с выпиской идёт по ним, а
не одной цифрой; неизвестное обязано оставаться пробелом. Тикет чинит отчётную
сторону: расхождение объясняется по частям, а пробелы правил делают прогноз
неполным, а не молчаливо нулевым.

**Сегодня.** Сверка — одно число (`ObservedBalance`,
`finance_core/settlements.py:277`); расхождение — одно подозрение «правило
начисления не совпало»; пробелы (`Gap`, `finance_core/roll.py:161`) — по
ставке, графику и кошельку; неполнота прогноза — `Forecast.complete`.

**Будет.** Наблюдение может быть и одной суммой, и по частям; расхождение
называет часть и причину (правило начисления, штраф, пошлина). Пробелы
расширяются: нет шкалы неустойки — неустойка не считается; нет порядка
распределения — платёж по частям не распределён. С пробелами прогноз неполный;
сошедшаяся сверка вопросов не даёт; `None` остаётся «не оценено», не нулём.

**Решения грилла плана.** Исполняет R2-Q10 (канон — сумма частей, сверка
получает разбивку, расхождение объясняется по частям, неизвестное —
`None`/пробел), R3-Q12 (нет правила — пробел, а не умолчание). Новых решений не
принимает.

**Blocked by:** 02 (формы и «правило не задано»), 04 (части), 06 (начисленная
неустойка в прогнозе).

## Приёмка

- [ ] Синтетика: наблюдение по частям сверяется по частям; расхождение по
  одной части называет её и причину, сошедшаяся сверка вопросов не даёт —
  `tests/test_forecast.py`.
- [ ] Синтетика: наблюдение одной суммой сверяется с суммой частей; расхождение
  объясняется по частям — `tests/test_forecast.py`.
- [ ] Синтетика: сделка без шкалы неустойки или без порядка распределения
  даёт пробел и делает прогноз неполным, а не нулевым — `tests/test_forecast.py`.
- [ ] Синтетика: книга без правила распределения — сверка идёт по итогу,
  разбивка по частям — пробел, прогноз неполный (Q34) —
  `tests/test_forecast.py`.
- [ ] Синтетика: неизвестное не подставляется нулём — признак «не оценено»
  (`None`) не выдаётся за отсутствие нехватки, ступень не объявляется
  достигнутой — `tests/test_forecast.py`.

## Грилл тикета

План решил **что** строить (R2-Q10, R3-Q12 — приняты), тикет решает **как**:
форма наблюдения по частям, форма вопроса при расхождении, форма пробелов
правил. Фронтюр раунда 1: наблюдение, вопросы, пробелы. Сверка — отчётная
сторона: считает её книга (04) и канон, тикет называет расхождения и неполноту.

### Раунд 1 — наблюдение по частям, вопросы, пробелы

❓ **12-Т1** — **Наблюдение по частям: форма `ObservedBalance`**: сегодня
наблюдение — одно число на дату (`finance_core/settlements.py:277`); R2-Q10 —
«наблюдение может быть и одной суммой, и по частям».

➡️ Рекомендация (принята): `ObservedBalance` получает **`parts:
tuple[PartPayment, ...] = ()`** — разбивка наблюдения по частям (та же форма
строки, что у разбивки движения: `PartPayment(part, amount)`); пусто — одной
суммой. Валидация: части из `PARTS`, без повторов, суммы не отрицательны;
сумма строк, если разбивка есть, — итог наблюдения (при расхождении с полем
`amount` — ошибка данных, а не тихий выбор одного из двух). **При неизвестной
раскладке (Q34) частей у расчёта нет:** сверка идёт по итогу (наблюдение одной
суммой против канона), расхождение по частям не называется, прогноз неполный —
части не выдумываются.

*Отклонено:*
- **отдельные записи наблюдения на каждую часть** — разъедутся по датам и
  потеряют «одно наблюдение»;
- **`dict[str, Decimal]`** — модель держит строки-пары (`PartPayment`);
- **наблюдение только по частям** (итог необязателен) — кредитор часто даёт
  одну цифру, выпрашивание разбивки рождает выдуманные.

❓ **12-Т2** — **Вопрос при расхождении: форма и содержание**: сегодня
расхождение — «наблюдение минус расчёт» одним числом, и причина подозревается
общая («правило начисления не совпало»); R2-Q10 — «расхождение объясняется по
частям — какая часть не сошлась и почему».

➡️ Рекомендация (принята): вопрос прогноза называет **часть и причину**:
строка вида «{сделка}: {часть} — наблюдение {X} против расчёта {Y}» (форма
строки — свободный текст в существующем списке `questions`, как сегодня у
расхождения); причины — те же, что сегодня, но привязанные к части: правило
начисления, штраф, пошлина, комиссия. Сошедшаяся сверка вопросов не даёт
(существующее правило сохраняется).

*Отклонено:*
- **оставить одно число** — R2-Q10 требует назвать часть: «правило начисления
  не совпало» — одно подозрение на все случаи;
- **структурировать вопрос в dataclass** — `questions` — список строк,
  ломать его форму ради одной причины не нужно;
- **показывать расхождение и как «неполноту»** — расхождение это вопрос
  (закрывается данными), неполнота — про неизвестное (12-Т3).

❓ **12-Т3** — **Пробелы правил и неполнота**: R3-Q12 — «нет шкалы — неустойка
не считается и сделка перечисляется пробелом; нет порядка распределения —
платёж по частям не распределён»; пробел делает прогноз неполным, а не нулевым.

➡️ Рекомендация (принята): пробелы пополняются двумя причинами в том же списке
`Gap` (строки, как `_gap_reason`): «шкала неустойки не задана — неустойка не
считается» и «порядок распределения платежа не задан — платёж по частям не
распределён»; обе делают `Forecast.complete` ложным (как сегодня пробелы
ставки и графика). Сделка без правила **в прокат не входит** (существующее
правило `_rollable` сохраняется) и перечисляется пробелом — не нулём.

*Отклонено:*
- **считать неустойку нулём при отсутствии шкалы** — выдуманная уверенность
  (`unknown-is-not-zero`);
- **пробел только в прогнозе, не в прокате** — сделка вошла бы в прокат без
  правила и дала ложный срок;
- **молчаливое «по порядку»** — Q12 отверг.

Фронтюр после раунда 1: края («не оценено», сошедшаяся сверка, регулярный
расход) и структура тестов — раунд 2.

### Раунд 2 — края и структура тестов

❓ **12-Т4** — **Края: «не оценено», сошедшаяся сверка, регулярный расход**:
`None` — «не оценено», а не ноль (`unknown-is-not-zero`); сверка регулярного
расхода не о чем (остатка нет); наблюдение одной суммой должно сверяться с
суммой частей.

➡️ Рекомендация (принята):

- **`None` — «не оценено»**: неизвестный прожиточный минимум, неоценённая
  нехватка и неизвестный лимит кошелька остаются `None`; прогноз помечается
  неполным, ступень не объявляется достигнутой — поведение сохраняется и
  распространяется на новые пробелы (12-Т3);
- **наблюдение одной суммой** сверяется с суммой частей расчёта; расхождение
  объясняется по частям (какая часть дала разницу, если разбивка наблюдения
  есть, — по ней; если нет — по частям расчёта);
- **регулярный расход**: наблюдение по нему — ошибка (существующий текст
  «остатка нет — сверять нечего»), части и сверка к нему не применяются;
- **сошедшаяся сверка** (в т.ч. по частям) вопросов не даёт и прогноз неполным
  не делает.

*Отклонено:*
- **подставлять ноль вместо «не оценено»** — выдуманная уверенность;
- **считать расхождение неполнотой** — это вопрос, закрываемый данными;
- **сверять регулярный расход по частям** — остатка нет, сверять нечего.

❓ **12-Т5** — **Структура синтетических тестов**: что запирает сверку и
неполноту.

➡️ Рекомендация (принята): `tests/test_forecast.py`. Группы:

1. **Сверка по частям**: наблюдение с разбивкой — расхождение по одной части
   называет её и причину; наблюдение одной суммой — сверяется с суммой частей,
   расхождение объясняется по частям; сошедшаяся сверка вопросов не даёт;
   книга без правила распределения — сверка по итогу, разбивка пробел,
   прогноз неполный (Q34).
2. **Пробелы**: сделка без шкалы неустойки и сделка без порядка распределения
   дают пробел и делают прогноз неполным (не нулевым); сделка не входит в прокат.
3. **«Не оценено»**: неизвестный прожиточный минимум — ступени не измерены,
   прогноз неполный; признак `None` не выдаётся за отсутствие нехватки.
4. **Края**: регулярный расход — сверять нечего (существующее); наблюдение с
   разбивкой, не сходящейся с итогом, — ошибка данных.

*Отклонено:*
- **тест раскладки и канона** — тикет 04 (здесь сверка);
- **тест состояния просрочки** — тикет 05;
- **тест проката** — тикеты 08/09.

Фронтюр после раунда 2 пуст: сверка по частям, вопросы, пробелы, «не оценено» и
тесты определены; досрочка — тикет 14.
