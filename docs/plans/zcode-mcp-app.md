# План: финансовая панель для агента — ZCode MCP App

**Goal** — поставить панель личных финансов как ZCode MCP App: плагин с
MCP-сервером над `finance_core` и UI-страницей. Человек получает интерактивную
панель в двух поверхностях — виджет в чате на вызове инструмента и постоянную
панель сессии; агент получает расчётные инструменты и замкнутый цикл «человек
выбрал вариант в панели → агент видит выбор в контексте следующего хода →
объясняет цену и планирует». Один расчётный слой вместо одноразовых
визуализаций, которые агент собирает заново каждый ход.

**Done**

1. **Плагин.** Манифест `.zcode-plugin/plugin.json`: stdio-сервер и поверхности —
   виджет в чате (инструменты с `_meta.ui.resourceUri`) и постоянная панель
   (`ui.surfaces`, `availability: "session"`).
2. **Сервер.** Официальный MCP SDK. Язык — Python: сервер импортирует
   `finance_core` напрямую, без моста. Допущение «ZCode корректно работает с
   Python-сервером как носителем UI-ресурсов» проверяется тикетом 01; запасной
   план — тонкая Node-обёртка над Python-расчётом. Инструменты: прогноз,
   стратегии, взаиморасчёты, варианты — расчёт по книге зоны. Расчётные
   инструменты видимы модели (`visibility: ["model", "app"]`), служебные
   страницы — только странице (`["app"]`). UI ходят агрегаты, которые панель
   показывает; сырые личные данные через UI не транспортируются.
3. **Страница.** Официальный `App` из `@modelcontextprotocol/ext-apps`.
   Прототип интерфейса (демо-фрагмент 2026-10-22, вне репозитория) адаптируется:
   данные через `app.callServerTool` вместо зашитого JSON, `widgetState` хранит
   вкладку, стратегию и выбранный вариант, выбор варианта уходит в модель через
   `updateModelContext`, возможности хоста проверяются `getHostCapabilities()`.
   Лимит HTML-ресурса 4 МиБ соблюдён с запасом (страница около 36 КиБ).
4. **Приёмка.** Установка в дев-профиль и ручная проверка по скиллу
   `developing-mcp-apps`: запуск инструмента и рендер виджета в чате, ручное
   открытие панели, тема, закрытие и переоткрытие с восстановлением состояния,
   явный отказ при недоступных возможностях хоста.

**Scope** — новый репозиторий-потребитель (код плагина), вне этой архитектурной
зоны: toolchain сборки и UI-код чужеродны зоне движка. Движок не меняется.
Данные зоны читаются сервером по пути из `userConfig`; в коде плагина личных
данных нет. Контракт и координация работы — здесь.

**Constraints**

- Не публиковать и не ставить в продакшн-профиль без явной просьбы оператора.
- SDK закреплён в lockfile; расширения хоста (`zcode/widgetState`,
  `zcode/surface`) экспериментальные: отсутствие возможности не меняет семантику
  молча — панель называет её неподдержанной.
- Инварианты движка не трогаются: ноль зависимостей, ни одного личного числа.
- Секреты — в окружении или заголовках, не в видимых аргументах команды
  (правило манифеста).

**Context** — разбор варианта поставки и демо-панель сделаны 2026-10-22 в
диалоге с оператором; прототип UI и синтетический сценарий собраны и проверены
тогда же (каталог визуализаций сессии, данные синтетические). План заводит
прямой запрос оператора, а не заявка из `inbox/`.

**Tickets** — черновик разбивки (не тикеты; разбивка — `/to-tickets`):

- 01 — скелет плагина: манифест, сервер с инструментом прогноза, страница из
  прототипа, приёмка виджета в чате. Проверяет допущение про Python-сервер.
- 02 — постоянная панель `ui.surfaces`, `widgetState` и `updateModelContext`
  (выбор варианта виден агенту в следующем ходе).
- 03 — инструменты стратегий, взаиморасчётов и вариантов; сравнение
  «тянуть — реструктуризация — мост» на одной линии окна.
