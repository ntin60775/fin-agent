# Публикация в открытый репозиторий

Зона спроектирована так, чтобы её **можно было публиковать**: личных данных в ней
нет — это и было причиной разделения ([zone-split.md](../decisions/zone-split.md)).
Технически ничто не мешает: хука, блокирующего `git push`, здесь нет — он живёт в
финансовой зоне.

## Что проверено

| Проверка | Результат |
|---|---|
| Личные числа, имена кредиторов, банки, номера счетов | нет |
| История коммитов | вычищена 2026-09-11 (перезапись): следов нет, хеши после неё изменились |
| Абсолютные пути `/home/…` в отслеживаемых файлах | нет |
| Хук, блокирующий push | отсутствует (`.omp/extensions/` нет) |
| `.gitignore` закрывает производное | `.gitmark/`, `*-map.html`, `.scratch/`, `__pycache__/` |
| Ветка | `main` |
| Объём | ~640 КБ, 64 файла |

## Что сделать перед первым push

1. **История.** Правка рабочего дерева историю **не чистит**. Проверить:

   ```bash
   git log -p --all | grep -nE '[0-9] ?(₽|руб)|…[0-9]{4}'
   ```

   Плюс **глазами** — на имена кредиторов и названия банков: шаблоном их не
   поймать, а в заявках они появляются легко. Найдётся — переписать историю,
   **пока репозиторий не опубликован**. После первого push это уже невозможно:
   форки и кэши не отзываются.

2. **Лицензия.** `.omp/` и `docs/ontology.md` — пакет **OntoShip** (MIT,
   © Valera Kovalskii): `LICENSE` сохраняется, авторство указано в `README.md`.
   Лицензия на собственный код (`finance_core/`) — решение автора.

3. **README.md** — есть: что это, что умеет, принципы, происхождение.

## Как публиковать

```bash
cd fin-agent
git remote add origin git@github.com:<owner>/<repo>.git   # SSH, не HTTPS
git push -u origin HEAD
```

**Из финансовой зоны push невозможен.** Её хук блокирует `git push` по шаблону
команды — в том числе нацеленный на этот репозиторий. Публикация идёт только из
сессии, открытой здесь; это не запрет, а страховка.

## Обратная сторона

Опубликованный репозиторий **публичен навсегда**: история, форки, кэши поисковиков.
Если позже понадобится закрыть — удаление не отменяет копий. Поэтому пункт 1
делается до, а не после.
