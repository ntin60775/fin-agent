# Решение: движок вынесен в отдельную зону от финансовых данных

- Дата: 2026-09-11
- Статус: принято

## Контекст

Финансовая зона выросла в самодостаточную систему: правила, сценарии, тесты,
артефакт. При этом в одном репозитории оказались вещи разной природы:

- **выписки, письма, суммы** — то, что не должно покидать машину ни при каких
  условиях (в зоне стоит хук, запрещающий remote);
- **движок расчёта** — чистая логика без единого личного числа, которую наоборот
  полезно версионировать и показывать.

Пока они лежат вместе, границу приватности провести нельзя: разрешить remote
нельзя из-за данных, а версионировать движок отдельно — невозможно.

## Варианты

1. **Оставить как есть** — один репозиторий, движок внутри. Отпало: приватность
   всего репозитория диктуется самым чувствительным файлом, а движок остаётся
   неотчуждаемым.
2. **Два каталога в одном репозитории** (`agent/` + `finance/`). Отпало: граница
   приватности всё равно общая — отдать движок наружу, не отдав данные, нельзя.
3. **Два репозитория** — архитектурная зона (движок, тесты, KB, правила разработки)
   и финансовая (данные, сценарии, правила зоны).

## Решение

Вариант 3. Архитектурная зона — обычный проект разработки: у него своя база
знаний, свой dev-flow, своя история. Финансовая зона — приватный потребитель
движка: она подключает его как библиотеку и держит только данные и сценарии.

## Последствия

- **Движок обязан быть чистым**: ни одного личного числа, ни одного имени
  кредитора, даже в докстрингах и примерах. Проверяется глазами при каждом
  переносе (в первой версии просочилось личное имя в публичный API — переименовано).
- **Тесты делятся**: синтетические (движок, здесь) и сценарные с реальными цифрами
  (финансовая зона). Движок не должен знать про конкретного человека.
- **Каждое изменение движка — цикл разработки**: замысел → контракт → тикеты →
  код → синтетические тесты → ревью → сценарные тесты потребителя → версия.
- Финансовая зона подключает движок как **редактируемый** пакет (`pip install -e`):
  правка в движке сразу видна потребителю, как в dev-окружении. Границей служат
  **сценарные тесты потребителя** — их прогон обязателен после каждой правки
  движка (шаг 6 в `../reference/how-to-work.md`). Жёсткая граница версий
  (сборка wheel и пиннинг) — вариант на будущее, если понадобится.
