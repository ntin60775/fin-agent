# Решение: что зона кладёт в число прожиточного минимума

- Дата: 2026-09-24
- Статус: принято

## Контекст

Прожиточный минимум — порог, который считает зона и который движок вычитает из
переносимых остатков. Прогноз читает разовые передачи с житейским назначением
из `one_offs` — то есть они события кассы и уже уменьшили остаток. Старая
формулировка в `CONTEXT.md` велела класть такие передачи в число минимума («еда,
потраченная чужими руками, — та же еда»): если зона так сделает, одна и та же
трата вычитается дважды — один раз событием из остатка, второй раз частью
порога в свободных деньгах. Это второй по знаку дефект к тикету 01 плана
model-audit-fixes: там прожитое не вычитается — здесь вычтено дважды.
Контракт нужен один общий: что вообще можно класть в число.

## Варианты

1. **Класть в число передачи** — старая формулировка. Отпало: двойной учёт
   против остатка — событие уже списано, порог его не возвращает.
2. **Разбирать каждый случай по назначению** — «на еду» в минимум, без
   назначения нет. Отпало: правило привязано к тексту назначения, зона
   классифицирует каждую запись, а двойной учёт всплывает неявно и по-разному.
3. **Общее правило по признаку события:** в число минимума кладётся только то,
   что не является событием кассы.

## Решение

Вариант 3. Событие уже в остатке — в число минимума не кладётся. Семейная
передача — канонический пример под общее правило: она всегда событие кассы —
разовая в `one_offs`, по графику — платёж сделки, — а не особый случай; под
правило подходит любое событие кассы. Строка семьи в отчёте остаётся отдельной
(`forecast._family`) — правило про число порога, а не про видимость.

## Последствия

- Применение — на стороне финансовой зоны: число она готовит, порог приходит
  снаружи, код движка не меняется. Это решение — контракт для её правила.
- Двойного учёта нет ни в одну сторону: прожитое вычитается один раз —
  накопленным по окну (тикет 01 плана model-audit-fixes), — а списанное
  событием в порог не возвращается.
- `CONTEXT.md` («Прожиточный минимум») и `finance_core/README.md` приведены к
  правилу; строка «Передачи входят в минимум» в плане obligations переписана —
  в KB одно правило, а не два взаимоисключающих.
- Состав числа — не повод подставлять неизвестное: минимум, состав которого
  неизвестен, остаётся `None`, а не ноль
  ([unknown-is-not-zero.md](unknown-is-not-zero.md)).
