# finance-core — ядро расчёта личных финансов

Библиотека арифметики для личных финансов: **касса** (хватит ли денег, где дыра,
хватает ли прожить до прихода), **взаиморасчёты** (сколько я должен и сколько
должны мне) и **прокат** (когда закроются долги, считая вместе с кассой). Без
зависимостей — только стандартная библиотека Python, деньги в `Decimal`.

Это **архитектурная зона**: здесь живёт движок и всё для его разработки.
Финансовые данные сюда не попадают — они остаются в отдельной приватной
зоне-потребителе.

## Что умеет

| Вопрос | Функция |
|---|---|
| Хватит ли денег в периоде, где дыра и когда | `run()` → `Result.hole`, `hole_date` |
| Что не прошло из-за ёмкости кошелька и что перевести | `run()` → `Result.unsecured` |
| Сколько я должен и сколько должны мне | `counterparty_balance()`, `deal_balance()` |
| Когда закроются сделки и когда я выйду из долгов | `roll_deals()`, `roll_months()` |
| Когда владелец выберется и что даёт сдвиг одного параметра | `forecast()`, `forecast_shifts()` |

Полный список вопросов и правил — [finance_core/README.md](finance_core/README.md).

## Быстрый старт

```bash
python3 -m pytest tests/        # синтетические тесты — без личных данных
python3 -m pip install -e .     # поставить как библиотеку — необязательно
```

Требуется Python ≥ 3.11.

## Устройство

```
finance_core/  движок: model + касса (solver) + взаиморасчёты (settlements) + прокат (roll) + прогноз (forecast) + старые долги (debt)
tests/         синтетические тесты — без личных данных
inbox/         заявки от зоны-потребителя (вход в работу)
docs/          база знаний: reference, decisions, plans, ops
.omp/          правило зоны и конфигурация плагинов; навыки и команды приходят пакетом
CONTEXT.md     доменные термины
```

Точка входа для агента — [AGENTS.md](AGENTS.md); как работать —
[docs/reference/how-to-work.md](docs/reference/how-to-work.md); модель знаний —
[docs/ontology.md](docs/ontology.md).

## Принципы

- **Markdown + git — источник правды.** Производное (индекс `.gitmark/`, HTML-карта)
  регенерируется из markdown и не коммитится.
- **Ядро не знает личных чисел.** Ни одного имени кредитора, ни одной суммы — ни в
  коде, ни в тестах, ни в документах, ни в примерах докстрингов.
- **Неизвестное — `None`, а не ноль.** Подставленный ноль выдаёт выдуманную
  уверенность ([решение](docs/decisions/unknown-is-not-zero.md)).
- **Правило счёта живёт в коде**, а не в комментарии, и запирается тестом.
- **Заявка — не правка.** Потребитель описывает потребность в `inbox/`; решение
  рождается в грилле, а не из спешки одной сессии
  ([решение](docs/decisions/request-channel.md)).
